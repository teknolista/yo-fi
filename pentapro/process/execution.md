# PROCESS · Execution

Read [the development strategy](../../docs/DEVELOPMENT-STRATEGY.md) and the PentaPRO status index before a material increment. Use relevant project-local skills and the existing technical guidance; do not invoke every available skill by default.

For each completed or interrupted material increment, update the [pilot log](../../docs/DEVELOPMENT-LOG.md) with the governing change, tested revision, observed skill use, checks, gaps, handoffs, and next action. Keep product evidence in the owning PROOF record and link it from the pilot entry. Distinguish skill availability, observed selection, actual use, and measured effect.

At meaningful milestones, compare intended results with acceptance scenarios, escaped defects, review findings, rework, interventions, and available time or usage evidence. Use comparable tasks and disclose limits. A single pilot does not establish general effectiveness. Reusable skill changes belong in the Teknolista skills collection after an independently reviewable evaluation.
